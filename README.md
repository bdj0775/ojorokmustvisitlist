# 오조록의 제주 맛집 목록

책 읽기 좋은 민박 **오조록** 주인장이 손님을 위해 직접 고른 제주 맛집 목록.
서버·DB 없는 정적 사이트 하나로 동작하며, 맛집 추가·수정은 주인장 전용 화면에서 합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 뼈대 (헤더 · 히어로 · 지도 · 필터 · 카드 · 푸터) |
| `styles/` | 디자인 시스템 (아래 참고) |
| `config/` | 설정·태그·문구 — 코드와 분리해 둔 값들 |
| `app.js` | 동작 (3개 언어 전환, 필터/정렬, Leaflet 지도, 공유) |
| `styleguide.html` | 디자인 시스템 문서 — 브라우저로 열어보세요 |
| `admin.html` | **주인장 전용 맛집 관리 화면** — 웹·내 컴퓨터 양쪽에서 열립니다 (아래 참고) |
| `admin-storage.js` | 관리 화면이 맛집 목록을 읽고 쓰는 창구 (로컬/웹 두 가지) |
| `api/` | 서버 창구 — 비밀번호 확인, GitHub 저장 (손님에게 내려가지 않음) |
| `places.json` | 맛집 데이터 (보통은 `admin.html` 이 대신 고쳐줍니다) |
| `images/` | 장소 사진, 카톡 공유 미리보기 이미지(`og.png`) |
| `tools/validate-places.mjs` | `places.json` 검사기 (아래 참고) |
| `tools/check-contrast.mjs` | 색 대비 검사기 (아래 참고) |
| `tools/dev-server.mjs` | `npm run dev` 가 띄우는 개발 서버 (관리 화면의 저장도 담당) |
| `vercel.json` · `.vercelignore` | 배포 설정 — 무엇을 올리고 무엇을 뺄지 |
| `.github/workflows/deploy.yml` | 올릴 때마다 자동 검사 |

## 디자인 시스템

디자인 값을 코드 곳곳에 흩어놓지 않고 **토큰**으로 모아 한 곳에서 관리합니다.
`styleguide.html` 을 브라우저로 열면 색·글자·간격·부품을 한눈에 볼 수 있습니다
(이 문서는 토큰 파일을 직접 읽어 그리므로 설명과 실제가 어긋나지 않습니다).

> **UI 를 고칠 사람은 [DESIGN.md](DESIGN.md) 를 보세요.**
> 색·타이포·컴포넌트·제약·현재 상태를 한 문서에 정리해 뒀습니다.
> 처음 이 프로젝트를 접하는 디자이너에게 이 파일 하나만 건네면 됩니다.

```
styles/tokens.css      ← 색·글꼴·간격·모서리·그림자. 디자인을 바꾸려면 대개 여기만 고칩니다
styles/base.css        ← 태그 기본 모양(리셋), 접근성
styles/components.css  ← 부품: 버튼·카드·태그·배지·칩·스위치
styles/layout.css      ← 이 페이지의 배치: 헤더·히어로·지도·목록·푸터
```

토큰은 3단으로 나뉩니다.

| 단계 | 예 | 언제 고치나 |
|---|---|---|
| 원시 | `--blue-500` | 팔레트 자체를 바꿀 때 |
| 의미 | `--color-brand` | 용도별로 어떤 색을 쓸지 바꿀 때 |
| 컴포넌트 | `--btn-height-md` | 특정 부품 치수만 바꿀 때 |

컴포넌트 CSS는 **의미 토큰만** 참조합니다. 그래서 다크 모드가 `tokens.css` 아래쪽
의미 토큰 재정의 블록 하나로 동작합니다(원하지 않으면 그 블록을 지우면 됩니다).

### 자주 하는 변경

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 브랜드 색 바꾸기 | `tokens.css` 의 `--color-brand*` |
| 버튼 색 바꾸기 | `tokens.css` 의 `--color-accent*` |
| 글꼴 바꾸기 | `tokens.css` 의 `--font-sans` + `index.html` 의 글꼴 `<link>` |
| 전체 여백 넓히기 | `tokens.css` 의 `--space-*` |
| 모서리 둥글기 | `tokens.css` 의 `--radius-*` |
| 태그 추가 | `config/tags.mjs` 에 한 줄 (**이 한 곳이 전부** — 색은 그룹이 정하므로 CSS는 안 건드려도 됩니다) |
| 화면 문구 수정 | `config/strings.mjs` |
| 예약 링크·숙소 좌표 | `config/site.mjs` |

### 색을 바꾼 뒤에는 대비를 확인하세요

글자와 배경이 충분히 구분되지 않으면 제주 햇빛 아래 휴대폰에서 읽기 어렵습니다.
색 토큰을 고친 뒤 이 검사기를 돌리면 어떤 조합이 문제인지 알려줍니다:

```bash
node tools/check-contrast.mjs
```

주요 조합을 밝은 모드·어두운 모드 양쪽에서 계산해 WCAG AA(작은 글자 4.5:1)와 비교합니다.
GitHub 에 올릴 때도 자동으로 실행되지만 **배포를 막지는 않으므로**, 올리기 전에 직접 돌려보세요.

참고로 예약 버튼은 선명한 감귤색 위에 **흰 글자 대신 진한 글자**를 씁니다 —
흰 글자는 3.09:1 밖에 나오지 않아 기준 미달이기 때문입니다.

## 내 컴퓨터에서 확인하기

```bash
npm run dev
```

`http://localhost:5173` 이 열립니다. 파일을 고치고 브라우저를 새로고침하면 바로 반영됩니다.
같은 와이파이에 있는 휴대폰에서도 볼 수 있게 주소를 함께 알려주므로, **실제 폰으로 확인**해 보세요
(손님 대부분이 휴대폰으로 열어봅니다).

- `npm install` 은 필요 없습니다. 외부 패키지를 하나도 쓰지 않습니다. (Node.js 18 이상만 있으면 됩니다)
- 서버가 필요한 이유: `places.json` 을 불러오는 방식 때문에 `index.html` 을 더블클릭으로 열면 동작하지 않습니다.
- 끄려면 `Ctrl+C`.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run check` | 아래 검사 두 가지를 한 번에 |
| `npm run check:places` | `places.json` 검사 |
| `npm run check:contrast` | 색 대비 검사 |

## 인터넷에 올리기 (Vercel)

이 저장소는 조립 과정이 없는 정적 파일 묶음이라 **파일을 그대로 서비스하는 방식**을 씁니다.
Vercel 이 GitHub 저장소를 지켜보다가, `main` 에 뭔가 올라오면 자동으로 배포합니다.

연결은 처음 한 번만 하면 됩니다 (`Vercel 연결하기` 항목 참고).
그 뒤로는 **`git push` 만 하면 20초쯤 뒤 사이트에 반영**됩니다.

- `vercel.json` — 배포 설정 (조립 과정 없음, 폴더를 그대로 올림)
- `.vercelignore` — 사이트에 올리지 **않을** 파일 목록. 관리자 페이지가 여기 들어 있습니다.

### Vercel 연결하기 (처음 한 번만)

1. <https://vercel.com> 접속 → **Continue with GitHub** 으로 로그인
2. **Add New… → Project**
3. 목록에서 `ojorokmustvisitlist` 를 찾아 **Import**
4. 설정 화면은 **아무것도 건드리지 말고** 그대로 **Deploy**
   (`vercel.json` 에 필요한 설정이 이미 들어 있습니다)
5. 20초쯤 뒤 나오는 주소로 접속해 사이트가 뜨는지 확인

연결이 끝나면 GitHub Pages 는 꺼도 됩니다
(**Settings → Pages → Source** 를 `None` 으로).

### 관리자 페이지는 비밀번호로 잠겨 있습니다

`admin.html` 은 이제 인터넷에서도 열립니다. 대신 **비밀번호를 알아야** 고칠 수 있습니다.
검색에도 잡히지 않습니다(`noindex`).

설정하는 방법은 아래 [웹에서 맛집 고치기](#웹에서-맛집-고치기-처음-한-번만-설정) 를 보세요.

### 검사는 계속 돕니다

`places.json` 검사와 색 대비 검사는 GitHub 에 올릴 때마다 실행되며, 결과는 **Actions** 탭과
커밋 옆 체크 표시로 확인할 수 있습니다. 다만 검사가 실패해도 배포가 멈추지는 않으므로,
**올리기 전에 `npm run check` 를 직접 돌려보는 습관**을 권합니다.

## 맛집 추가/수정 — 주인장 화면

**두 곳에서 똑같이 쓸 수 있습니다.**

| 어디서 | 주소 | 저장하면 |
|---|---|---|
| 인터넷 (폰·아무 컴퓨터) | `배포주소/admin.html` | GitHub 에 바로 저장 → 20초쯤 뒤 손님 화면에 반영 |
| 내 컴퓨터 | `npm run dev` 후 `localhost:5173/admin.html` | 내 컴퓨터 파일만 바뀜 → `git push` 해야 반영 |

화면을 열면 **지금 어느 쪽인지 헤더에 표시**됩니다("웹에서 바로 저장" / "내 컴퓨터").
인터넷에서 열면 비밀번호를 먼저 묻습니다.

화면에서 할 수 있는 것:

- 맛집 **추가 · 수정 · 삭제**
- **영어·중국어 번역** 입력 (예전에는 `places.json` 을 직접 열어야 했습니다)
- **검색** — 이름·소개·메뉴·지역·태그로 찾기 (37곳이 넘어가면 스크롤이 힘듭니다)
- 아직 안 채운 것 표시 — 좌표 없음 / 번역 없음 / 소개 없음
- 구글맵 링크를 붙여넣으면 위도·경도를 자동으로 채워줍니다

번역을 비워두면 손님 화면에 한국어가 대신 나오므로 사이트는 깨지지 않습니다.

## 웹에서 맛집 고치기 (처음 한 번만 설정)

인터넷에서 고치려면 Vercel 에 값 두 개를 넣어야 합니다.
이 값들은 **서버에만** 있고 손님 브라우저로는 절대 내려가지 않습니다.

### 1. GitHub 열쇠(토큰) 만들기

1. <https://github.com/settings/personal-access-tokens/new> 접속
2. **Token name** 아무 이름 (예: `ojorok-admin`)
3. **Expiration** — 1년 정도로 넉넉히 (만료되면 관리 화면에서 안내가 뜹니다)
4. **Repository access** → **Only select repositories** → `ojorokmustvisitlist` 선택
5. **Permissions** → **Repository permissions** → **Contents** 를 **Read and write** 로
6. **Generate token** → 나온 값을 복사 (이 화면을 닫으면 다시 볼 수 없습니다)

> 저장소 하나에만, 파일 수정 권한만 준 열쇠입니다.
> 혹시 새어나가도 이 저장소 밖으로는 아무것도 할 수 없습니다.

### 2. Vercel 에 값 넣기

Vercel → 프로젝트 → **Settings** → **Environment Variables** 에서 두 개를 추가합니다.

| 이름 | 값 |
|---|---|
| `GITHUB_TOKEN` | 위에서 복사한 열쇠 |
| `ADMIN_PASSWORD` | 관리 화면에 들어갈 때 칠 비밀번호 (직접 정하세요) |

비밀번호는 **길게** 잡으세요. 짧으면 찍어서 뚫립니다.
(연속 10번 틀리면 10분간 잠기지만, 그것만 믿지는 마세요.)

넣은 뒤 **Deployments → 맨 위 배포의 ⋯ → Redeploy** 를 눌러야 값이 적용됩니다.

선택 사항으로 `SESSION_SECRET` 을 넣으면 로그인 상태가 비밀번호와 무관하게 유지됩니다.
넣지 않으면 비밀번호를 바꿀 때 모든 기기에서 자동 로그아웃되는데, 보통은 그게 더 안전합니다.

### 3. 확인

`배포주소/admin.html` 로 들어가 비밀번호를 치면 맛집 목록이 나옵니다.
고치고 저장하면 GitHub 에 커밋이 하나 생기고, Vercel 이 자동으로 다시 배포합니다.

무엇이 잘못되면 화면이 **한국어로 이유를 알려줍니다**
(열쇠 만료, 권한 부족, 설정 누락 등).

### 저장이 어긋나지 않게

관리 화면은 파일을 읽은 시점을 기억해 뒀다가, 저장할 때 그 사이 다른 곳에서
바뀌지 않았는지 확인합니다. 바뀌었으면 덮어쓰지 않고 **새로고침하라고 알려줍니다**.
폰과 노트북에서 동시에 고쳐도 한쪽 작업이 조용히 사라지지 않습니다.

### 번역을 채울 때 — 상호명은 한글을 남기세요

```
"name": {
  "ko": "남양수산",
  "en": "Namyang Susan (남양수산)",
  "zh": "南洋水產 (남양수산)"
}
```

외국 손님이 **택시 기사에게 보여주거나 간판을 찾을 때 한글이 필요**합니다.
의미만 옮기면(`Namyang Fish Market`) 정작 현장에서 쓸 수 없습니다.
원래 로마자 상호가 있는 곳(프릳츠 → Fritz)은 그것을 쓰고, 없으면 발음을 옮깁니다.

### 관리 화면은 어떻게 만들어져 있나

"어디에 저장하는가" 는 `admin-storage.js` 가 혼자 담당합니다.
방식이 두 개 들어 있고, 화면을 열 때 쓸 수 있는 쪽을 자동으로 고릅니다.

| 파일 | 역할 |
|---|---|
| `admin.js` | 화면 동작. **어디에 저장하는지 모릅니다** |
| `admin-storage.js` | 저장 창구 두 개(로컬/웹)와 자동 선택 |
| `api/login.mjs` | 비밀번호 확인, 출입증(쿠키) 발급 |
| `api/places.mjs` | 맛집 목록 읽기/쓰기 (로그인한 사람만) |
| `api/_github.mjs` | GitHub 에 커밋하는 부분 |
| `api/_auth.mjs` | 출입증 서명·확인, 연속 실패 잠금 |

`api/` 안의 파일은 **서버에서만** 돕니다. 손님 브라우저로 내려가지 않으므로
여기에서만 GitHub 열쇠를 다룰 수 있습니다.

## 직접 파일을 고칠 때 — `places.json`

- 파일 상단 `_안내` 항목에 편집 방법이 적혀 있고, `_예시` 항목을 복사해서 시작하면 됩니다.
- `en` / `zh` 번역이 비어 있으면 자동으로 한국어가 표시되므로 **한국어만 채워도 사이트가 깨지지 않습니다.**
- `tags` 에 쓸 수 있는 값은 `config/tags.mjs` 에 있습니다 (업종·음식·특징 3개 그룹, 25개).
- 현재 들어 있는 2곳은 **예시 데이터**입니다. 실제 맛집으로 교체하세요.

### 고친 뒤 검사하기

손으로 JSON을 고치다 보면 쉼표 하나 때문에 사이트가 빈 화면이 되기 쉽습니다. 올리기 전에 한 번 돌려보세요:

```bash
node tools/validate-places.mjs
```

빠진 항목, 중복된 `id`, 등록되지 않은 태그, 위도·경도를 바꿔 넣은 실수, 없는 사진 파일까지 짚어줍니다.
GitHub 에 올릴 때도 자동으로 실행되지만 **배포를 막지는 않으므로**, 올리기 전에 직접 돌려보는 편이 안전합니다.

   (지금은 오조포구 근처 근사값. '가까운 순' 정렬의 기준점입니다)
3. 맛집 사진 — `images/` 에 넣고 `places.json` 의 `photo` 에 파일명을 적습니다.
   지금 카드는 사진을 표시하지 않지만, 값은 그대로 보관됩니다.

### 주소에서 `vercel` 빼기 (내 도메인 연결)

`.vercel.app` 은 Vercel 이 무료로 주는 주소라 **바꿀 수는 없고, 내 도메인을 사서 얹는** 방식입니다.
도메인을 연결해도 기존 주소는 계속 살아 있으니 QR 코드를 이미 뿌렸어도 괜찮습니다.

**1. 도메인 사기** — 아래 중 한 곳에서 삽니다 (연 단위 결제).

| 후보 | 느낌 | 대략 연 비용 |
|---|---|---|
| `ojorok.com` | 가장 무난. 외국 손님도 익숙 | 2만원 안팎 |
| `ojorok.kr` / `ojorok.co.kr` | 한국 숙소라는 게 분명함 | 1~2만원 |
| `ojorok.me` / `ojorok.co` | 짧고 개인 브랜드 느낌 | 2~4만원 |
| `ojorok.jeju` | 제주 전용 도메인 | 판매처가 적음 |

파는 곳: [가비아](https://www.gabia.com), [후이즈](https://whois.co.kr) (한국어·카드결제 편함) /
[Cloudflare](https://www.cloudflare.com/products/registrar/), [Namecheap](https://www.namecheap.com) (더 쌈, 영어)

> **Vercel 에서 바로 사도 됩니다.** 조금 비싸지만 아래 2번 설정이 자동으로 끝나서 가장 쉽습니다.
> (Vercel → 프로젝트 → Settings → Domains → 원하는 이름 검색 → Buy)

**2. Vercel 에 연결하기**

1. Vercel → 프로젝트 → **Settings** → **Domains**
2. 산 도메인을 적고 **Add**
3. Vercel 이 알려주는 값을 도메인 산 곳의 **DNS 설정**에 그대로 입력
   - 보통 `A` 레코드 `76.76.21.21` 또는 `CNAME` → `cname.vercel-dns.com`
4. 10분~1시간쯤 기다리면 자물쇠(https)까지 자동으로 붙습니다

**3. 코드에서 고칠 곳 — 딱 두 줄**

`index.html` 위쪽의 이 두 줄만 새 주소로 바꾸면 됩니다. (`★` 표시를 해 뒀습니다)

```html
<meta property="og:url"   content="https://새주소/" />
<meta property="og:image" content="https://새주소/images/og.png?v=3" />
```

`og:image` 끝의 숫자(`?v=2` → `?v=3`)도 하나 올려주세요.
안 그러면 카톡이 예전 주소로 받아둔 그림을 계속 씁니다.

**4. 마무리**

- 새 주소로 QR 코드를 다시 만들어 숙소 안내판을 교체
- 카톡에 링크를 한 번 보내 미리보기가 제대로 뜨는지 확인
  (안 뜨면 [카카오 디버거](https://developers.kakao.com/tool/debugger/sharing) 에서 새로 읽기)
- 네이버·에어비앤비 숙소 소개란의 링크도 새 주소로

> 관리자 화면(`/admin.html`)은 주소가 바뀌어도 그대로 따라옵니다. 고칠 것이 없습니다.

### 도메인을 아직 안 살 거라면

`.vercel.app` 주소를 그대로 써도 사이트는 아무 문제 없이 돕니다.
손님에게 건네는 건 대부분 **QR 코드나 카톡 링크**라 주소를 직접 칠 일이 거의 없습니다.
급하지 않으니 이름을 충분히 고민한 뒤에 사셔도 됩니다.
