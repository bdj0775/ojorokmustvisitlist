# 오조록의 제주 맛집 목록

책 읽기 좋은 민박 **오조록** 주인장이 손님을 위해 직접 고른 제주 맛집 목록.
서버·DB 없는 정적 사이트 하나로 동작하며, 맛집 추가·수정은 주인장 전용 화면에서 합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 뼈대 (헤더 · 히어로 · 지도 · 필터 · 카드 · 푸터) |
| `styles/` | 디자인 시스템 (아래 참고) |
| `config/` | 설정·태그·문구 — 코드와 분리해 둔 값들 |
| `app.js` | 동작 (3개 언어 전환, 필터/정렬, Leaflet 지도, 공유) |
| `styleguide.html` | 디자인 시스템 문서 — 브라우저로 열어보세요 |
| `admin.html` | **주인장 전용 맛집 관리 화면** — 내 컴퓨터에서만 열립니다 (아래 참고) |
| `admin-storage.js` | 관리 화면이 맛집 목록을 읽고 쓰는 창구 |
| `places.json` | 맛집 데이터 (보통은 `admin.html` 이 대신 고쳐줍니다) |
| `images/` | 장소 사진, OG 공유 이미지(`og.jpg`) |
| `tools/validate-places.mjs` | `places.json` 검사기 (아래 참고) |
| `tools/check-contrast.mjs` | 색 대비 검사기 (아래 참고) |
| `tools/dev-server.mjs` | `npm run dev` 가 띄우는 개발 서버 (관리 화면의 저장도 담당) |
| `vercel.json` · `.vercelignore` | 배포 설정 — 무엇을 올리고 무엇을 뺄지 |
| `.github/workflows/deploy.yml` | 올릴 때마다 자동 검사 |

## 디자인 시스템

디자인 값을 코드 곳곳에 흩어놓지 않고 **토큰**으로 모아 한 곳에서 관리합니다.
`styleguide.html` 을 브라우저로 열면 색·글자·간격·부품을 한눈에 볼 수 있습니다
(이 문서는 토큰 파일을 직접 읽어 그리므로 설명과 실제가 어긋나지 않습니다).

```
styles/tokens.css      ← 색·글꼴·간격·모서리·그림자. 디자인을 바꾸려면 대개 여기만 고칩니다
styles/base.css        ← 태그 기본 모양(리셋), 접근성
styles/components.css  ← 부품: 버튼·카드·태그·배지·칩·스위치
styles/layout.css      ← 이 페이지의 배치: 헤더·히어로·지도·목록·푸터
```

토큰은 3단으로 나뉩니다.

| 단계 | 예 | 언제 고치나 |
|---|---|---|
| 원시 | `--blue-500` | 팔레트 자체를 바꿀 때 |
| 의미 | `--color-brand` | 용도별로 어떤 색을 쓸지 바꿀 때 |
| 컴포넌트 | `--btn-height-md` | 특정 부품 치수만 바꿀 때 |

컴포넌트 CSS는 **의미 토큰만** 참조합니다. 그래서 다크 모드가 `tokens.css` 아래쪽
의미 토큰 재정의 블록 하나로 동작합니다(원하지 않으면 그 블록을 지우면 됩니다).

### 자주 하는 변경

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 브랜드 색 바꾸기 | `tokens.css` 의 `--color-brand*` |
| 버튼 색 바꾸기 | `tokens.css` 의 `--color-accent*` |
| 글꼴 바꾸기 | `tokens.css` 의 `--font-sans` + `index.html` 의 글꼴 `<link>` |
| 전체 여백 넓히기 | `tokens.css` 의 `--space-*` |
| 모서리 둥글기 | `tokens.css` 의 `--radius-*` |
| 태그 추가 | `config/tags.mjs` 에 한 줄 (**이 한 곳이 전부** — 색은 그룹이 정하므로 CSS는 안 건드려도 됩니다) |
| 화면 문구 수정 | `config/strings.mjs` |
| 예약 링크·숙소 좌표 | `config/site.mjs` |

### 색을 바꾼 뒤에는 대비를 확인하세요

글자와 배경이 충분히 구분되지 않으면 제주 햇빛 아래 휴대폰에서 읽기 어렵습니다.
색 토큰을 고친 뒤 이 검사기를 돌리면 어떤 조합이 문제인지 알려줍니다:

```bash
node tools/check-contrast.mjs
```

주요 조합을 밝은 모드·어두운 모드 양쪽에서 계산해 WCAG AA(작은 글자 4.5:1)와 비교합니다.
GitHub 에 올릴 때도 자동으로 실행되지만 **배포를 막지는 않으므로**, 올리기 전에 직접 돌려보세요.

참고로 예약 버튼은 선명한 감귤색 위에 **흰 글자 대신 진한 글자**를 씁니다 —
흰 글자는 3.09:1 밖에 나오지 않아 기준 미달이기 때문입니다.

## 내 컴퓨터에서 확인하기

```bash
npm run dev
```

`http://localhost:5173` 이 열립니다. 파일을 고치고 브라우저를 새로고침하면 바로 반영됩니다.
같은 와이파이에 있는 휴대폰에서도 볼 수 있게 주소를 함께 알려주므로, **실제 폰으로 확인**해 보세요
(손님 대부분이 휴대폰으로 열어봅니다).

- `npm install` 은 필요 없습니다. 외부 패키지를 하나도 쓰지 않습니다. (Node.js 18 이상만 있으면 됩니다)
- 서버가 필요한 이유: `places.json` 을 불러오는 방식 때문에 `index.html` 을 더블클릭으로 열면 동작하지 않습니다.
- 끄려면 `Ctrl+C`.

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run check` | 아래 검사 두 가지를 한 번에 |
| `npm run check:places` | `places.json` 검사 |
| `npm run check:contrast` | 색 대비 검사 |

## 인터넷에 올리기 (Vercel)

이 저장소는 조립 과정이 없는 정적 파일 묶음이라 **파일을 그대로 서비스하는 방식**을 씁니다.
Vercel 이 GitHub 저장소를 지켜보다가, `main` 에 뭔가 올라오면 자동으로 배포합니다.

연결은 처음 한 번만 하면 됩니다 (`Vercel 연결하기` 항목 참고).
그 뒤로는 **`git push` 만 하면 20초쯤 뒤 사이트에 반영**됩니다.

- `vercel.json` — 배포 설정 (조립 과정 없음, 폴더를 그대로 올림)
- `.vercelignore` — 사이트에 올리지 **않을** 파일 목록. 관리자 페이지가 여기 들어 있습니다.

### Vercel 연결하기 (처음 한 번만)

1. <https://vercel.com> 접속 → **Continue with GitHub** 으로 로그인
2. **Add New… → Project**
3. 목록에서 `ojorokmustvisitlist` 를 찾아 **Import**
4. 설정 화면은 **아무것도 건드리지 말고** 그대로 **Deploy**
   (`vercel.json` 에 필요한 설정이 이미 들어 있습니다)
5. 20초쯤 뒤 나오는 주소로 접속해 사이트가 뜨는지 확인

연결이 끝나면 GitHub Pages 는 꺼도 됩니다
(**Settings → Pages → Source** 를 `None` 으로).

### 관리자 페이지는 사이트에 올라가지 않습니다

`admin.html` 은 `.vercelignore` 에 적혀 있어 배포에서 빠집니다.
내 컴퓨터에서 `npm run dev` 로 켤 때만 열립니다.

### 검사는 계속 돕니다

`places.json` 검사와 색 대비 검사는 GitHub 에 올릴 때마다 실행되며, 결과는 **Actions** 탭과
커밋 옆 체크 표시로 확인할 수 있습니다. 다만 검사가 실패해도 배포가 멈추지는 않으므로,
**올리기 전에 `npm run check` 를 직접 돌려보는 습관**을 권합니다.

## 맛집 추가/수정 — 주인장 화면

내 컴퓨터에서만 씁니다. 인터넷에는 올라가지 않습니다.

```powershell
npm run dev
```

를 켠 뒤 `http://localhost:5173/admin.html` 로 들어갑니다.

폼을 채우고 **저장하기** 를 누르면 내 컴퓨터의 `places.json` 이 바로 바뀝니다.
**아직 손님 화면에는 반영되지 않습니다.** 화면 아래 "손님 화면에 올리기" 에 적힌 대로
`git push` 까지 해야 실제 사이트에 나갑니다.

- 등록된 목록에서 **수정 / 삭제** 도 됩니다 (가게가 폐업하면 삭제).
- 구글맵 링크를 붙여넣으면 위도·경도를 자동으로 채워줍니다.
- 예전에는 이 화면이 GitHub 에 직접 커밋해서 열쇠(토큰)가 필요했습니다.
  지금은 내 파일을 직접 고치므로 열쇠가 필요 없고, 내 컴퓨터 파일이 옛날 버전으로
  남아 어긋나는 문제도 사라졌습니다.

입력한 이름·소개는 한국어로만 저장됩니다. 영어·중국어 번역은 비어 있으면
자동으로 한국어가 대신 나오므로 사이트는 깨지지 않고, 번역은 나중에 `places.json` 에 채우면 됩니다.

### 나중에 웹에서 쓰고 싶어지면

"어디에 저장하는가" 는 `admin-storage.js` 가 혼자 담당합니다.
그 파일에 GitHub 방식을 하나 더 만들어 붙이면 웹에서도 쓸 수 있고,
`admin.js` 는 고칠 필요가 없습니다. 그때는 다시 GitHub 열쇠(토큰)가 필요합니다 —
웹에서는 "이 사람이 진짜 주인장인가" 를 확인할 방법이 그것뿐이기 때문입니다.

## 직접 파일을 고칠 때 — `places.json`

- 파일 상단 `_안내` 항목에 편집 방법이 적혀 있고, `_예시` 항목을 복사해서 시작하면 됩니다.
- `en` / `zh` 번역이 비어 있으면 자동으로 한국어가 표시되므로 **한국어만 채워도 사이트가 깨지지 않습니다.**
- `tags` 에 쓸 수 있는 값은 `config/tags.mjs` 에 있습니다 (업종·음식·특징 3개 그룹, 25개).
- 현재 들어 있는 2곳은 **예시 데이터**입니다. 실제 맛집으로 교체하세요.

### 고친 뒤 검사하기

손으로 JSON을 고치다 보면 쉼표 하나 때문에 사이트가 빈 화면이 되기 쉽습니다. 올리기 전에 한 번 돌려보세요:

```bash
node tools/validate-places.mjs
```

빠진 항목, 중복된 `id`, 등록되지 않은 태그, 위도·경도를 바꿔 넣은 실수, 없는 사진 파일까지 짚어줍니다.
GitHub 에 올릴 때도 자동으로 실행되지만 **배포를 막지는 않으므로**, 올리기 전에 직접 돌려보는 편이 안전합니다.
